# Product Strategy

## When to Use
- After validation: turning an opportunity into a product definition
- MVP scoping, feature prioritization, pricing, launch strategy
- "What should we build first?" questions

## Procedure
1. Start from the validated opportunity: customer, problem, evidence. Do not skip validation.
2. Define:
   - Product thesis (one sentence: for whom, solving what, why now)
   - Customer and workflow
   - MVP (the smallest thing that tests the riskiest assumption)
   - User journey
   - Features prioritized:
     ```text
     MUST HAVE
     SHOULD HAVE
     LATER
     DO NOT BUILD
     ```
   - Evaluation: how will success be measured?
   - Pricing (per business-model-analysis)
   - Launch strategy (distribution reality, channels, partners)
3. The MVP must be testable: a hypothesis, a metric, a failure threshold.
4. Localize: language, payments, connectivity, low-bandwidth usage, phone-first UX, trust.

## Output Format
```text
Product thesis
Customer & workflow
MVP definition
Feature priorities (MUST/SHOULD/LATER/DON'T)
Success metrics
Pricing
Launch plan
Validation loop for the MVP
```

## Pitfalls
- Building features before validating the riskiest assumption
- US-centric UX assumptions (email-first, desktop, cards)
- Skipping the DO NOT BUILD list

## Verification
- MVP is minimal and tests a named hypothesis
- Success metric and failure threshold defined
- Launch plan matches distribution reality
